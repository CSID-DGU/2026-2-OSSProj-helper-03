# ui

Helper의 화면(준비 화면, 보조 화면, 설정 화면)입니다. React + Vite + TypeScript.

엔진(로컬 서버)과는 WebSocket(`ws://localhost:8000/ws`) 하나로만 주고받습니다. 엔진이 아직 없을 때는 같은 주소에서 도는 **모의 서버**로 개발합니다.

## 실행

Node.js 22.18 이상이 필요합니다 (모의 서버를 `node mock/server.ts`로 바로 실행하기 때문).

```bash
npm install
npm run mock   # 터미널 1: 모의 서버 (ws://localhost:8000/ws)
npm run dev    # 터미널 2: 화면 (http://localhost:5173)
```

시작 패널에서 소리 입력을 고르고 **보조 화면 시작**을 누릅니다. 모의 서버는 고른 입력에 따라 다르게 동작합니다.

| 소리 입력 | 모의 서버 | 실서버 |
|---|---|---|
| 음성 파일 | 샘플 대본(`mock/sample_cues.csv`)으로 정해 둔 시나리오 재생 | 녹음 파일 재생 |
| 마이크 | 음성 파일과 같은 시나리오 (마이크는 흉내만) | 아직 이 선택을 읽지 않음. 서버 `.env`의 `HELPER_INPUT`을 따름 |
| 대사 입력 (테스트) | 입력한 대사를 대본과 비교해 위치·이탈을 보냄 (간단한 글자 유사도) | 아직 지원 안 함 (엔진 담당에 요청) |

시나리오: 정상 진행 → 애드리브(#108 뒤) → 누락(#113 건너뜀) → 노래 구간(#115~118) → 반복(#121 다시) → 입력 끊김 → 정상 진행

**대사 입력 모드**로 녹음·마이크·음성인식 키 없이 테스트할 수 있습니다. 화면 아래 입력창에 배우가 한 말을 치고 Enter를 누르면 음성인식 결과 한 번으로 보고 추적합니다. "다음 대사 채우기"는 현재 위치 다음 대사를 입력창에 넣어 줍니다. 대본에 없는 말을 치면 애드리브, 몇 줄 건너뛰면 누락, 앞 대사를 다시 치면 반복으로 처리합니다. 모의 서버의 판단은 실제 엔진과 다르므로, 엔진이 `test.say`를 지원하면 실제 추적기로 확인할 수 있습니다.

| 환경 변수 | 기본값 | 설명 |
|---|---|---|
| `MOCK_PORT` | `8000` | 모의 서버 포트 |
| `MOCK_TICK_MS` | `1500` | 메시지를 보내는 간격 (인식 주기 1~2초 가정) |
| `VITE_ENGINE_URL` | `ws://localhost:8000/ws` | 화면이 연결할 주소. `.env.local`에 적습니다 |

실서버(FastAPI)가 생기면 모의 서버를 끄고 실서버를 8000번 포트로 띄우면 화면은 그대로 동작합니다.

## 보조 화면 동작

화면 배치:

- 위: 공연 이름 · 경과 시간 · 소리 입력 | 음향 입력 상태 · 대사/노래 구간 · 처리 지연 · 회차 종료
- 왼쪽: 대본 목록 (항상 같은 높이)
- 오른쪽 (위에서부터 고정 순서): 이탈 알림 카드 → 애드리브 임시 자막 (평소에는 제목 한 줄, 이탈하면 펼쳐짐) → 관객 휴대폰 미리보기 → 이탈 기록
- 아래: 팀용 도구 (대사 입력 테스트 · 성능 확인용 표). 점선 테두리로 오퍼레이터 화면과 구분
- 폭이 760px보다 좁으면 한 줄로: 알림 → 애드리브 임시 자막 → 대본 목록 → 휴대폰 미리보기 → 이탈 기록

이탈해도 대본 목록 높이와 각 영역의 순서가 바뀌지 않게 해서, 공연 중에 보던 자리가 움직이지 않습니다.

| 상황 | 알림 카드 | 대본 목록 |
|---|---|---|
| 정상 | 대본대로 진행 중 | 추정 위치 줄 강조, 가운데로 따라감 |
| 신뢰도가 기준(0.6) 미만 | 변화 없음 | 강조 줄이 점선, "불확실" |
| 이탈 중 | 빨간 카드: 유형, 경과 시간 | |
| 대본 복귀 | 밝은 카드: 복귀 큐 번호를 크게, 10초 뒤 "최근 복귀" 한 줄로 | 복귀 줄에 "복귀" 표시 |
| 노래 구간 | 알림 보류 카드 (연두색 배지) | 가사 줄을 따라감 (엔진이 현재 큐가 가사면 노래 구간으로 보고 이탈 알림만 보류) |
| 입력 없음 | 알림 보류 카드 | 강조 줄을 흐리게 |
| 연결 끊김 / 5초간 메시지 없음 | 회색 카드 + 빨간 점선 테두리: 기존 방식대로 송출 | |

이탈이 시작되면 화면 가장자리가 빨강으로 3번(1.5초) 깜빡인 뒤 얇은 빨간 테두리가 남고, 복귀하면 파랑으로 3번 깜빡입니다. 오퍼레이터가 송출 프로그램을 보고 있어도 곁눈으로 알 수 있게 하기 위해서입니다. 운영체제의 "움직임 줄이기"가 켜져 있으면 깜빡이지 않고 한 번만 천천히 켜졌다 꺼집니다.

이탈 기록에는 이번 회차의 이탈이 최신순으로 남습니다 (시각, 유형, 걸린 시간, 복귀 큐). 회차를 종료하면 지워집니다.

상단에는 회차를 시작한 뒤 흐른 시간과 소리 입력 모드가 보입니다.

**AI 추정 / 실제로 들린 말**은 오퍼레이터용이 아니라 팀의 성능 확인용이라 기본으로 접혀 있고, 화면 맨 아래 "성능 확인용" 줄을 누르면 펼쳐집니다(접혀 있어도 기록은 계속 쌓임). 인식 결과마다 한 줄씩 쌓입니다(최신이 위). 왼쪽은 AI가 고른 큐 번호와 대사, 오른쪽은 들린 시각(회차 시작 기준, 처리 지연을 뺀 값)과 인식 글자입니다. 둘을 비교하면 추적이 맞는지, 어디서 어긋났는지 바로 보입니다. 신뢰도가 기준보다 낮으면 "불확실"로 표시합니다.

**관객 휴대폰 미리보기**는 관객이 보게 될 자막 모양을 작게 보여 줍니다. 대사는 `[화자]`, 가사는 `♪`로 감쌉니다. 노래 구간에도 가사가 바뀌며 나옵니다. 실제로 송출된 큐는 2단계(송출 프로그램 연동) 전이라 받을 수 없어서, 지금은 AI가 추정한 큐로 보여 줍니다. 이탈 중에는 흐리게 표시합니다.

**애드리브 임시 자막**은 대본을 벗어나면 알림 카드 바로 아래에서 자동으로 펼쳐집니다. 이탈 중이 아닐 때도 "열기"로 펼칠 수 있습니다.

- ① **인식된 말**: 이탈 뒤 들린 말을 이어 붙여 보여 줍니다 (겹쳐 보낸 조각은 한 번만). 고치기 시작하면 자동 갱신을 멈추고, "최신 인식으로 다시 채우기"로 되돌릴 수 있습니다. 송출하면 비우고 그 뒤에 들린 말부터 다시 모읍니다.
- ② **직접 작성**: 오퍼레이터가 처음부터 써서 송출합니다.
- 실수로 송출하지 않게 Enter는 줄바꿈이고, **송출** 버튼이나 Ctrl+Enter로 송출합니다. 최근 송출 3건이 아래에 남습니다.
- 송출한 임시 자막은 관객 휴대폰 미리보기에 글자 그대로 나오고(관객 화면과 같게), 미리보기 아래에 "애드리브 임시 자막"이라고 따로 알려 줍니다. 다음 큐로 넘어가면 대본 자막으로 돌아갑니다.
- 쓰던 내용이 있으면 대본으로 복귀해도 닫히지 않습니다.

대본 목록을 손으로 스크롤하면 5초 동안 따라가기를 멈추고, "현재 위치로" 버튼이 나옵니다. 기준값은 `src/settings.ts`에 있습니다.

## 메시지

수행계획서 (5) 엔진과 화면 사이 인터페이스를 그대로 따릅니다. 필드가 확정되거나 바뀌면 `src/protocol.ts`만 고치면 됩니다.

| 메시지 | 방향 | 필드 |
|---|---|---|
| `session.start` / `session.end` | 화면 → 엔진 | `show_id`, `cue_file`, `input`(추가) |
| `test.say` (추가) | 화면 → 엔진 | `text` |
| `subtitle.send` (추가) | 화면 → 엔진 | `text`, `source` |
| `settings.update` | 화면 → 엔진 | `alert_threshold` |
| `position.update` | 엔진 → 화면 | `cue_id`, `confidence`, `latency_ms` |
| `deviation.alert` | 엔진 → 화면 | `deviation_type`, `since`, `return_cue_id` |
| `input.status` | 엔진 → 화면 | `audio_level`, `segment` |
| `cue.onair` (2단계) | 송출 프로그램 → 엔진 → 화면 | `cue_id`, `sent_at` |

모든 메시지는 `{"type": "position.update", "cue_id": 845, ...}`처럼 `type`에 메시지 이름을 넣은 JSON 하나입니다.

수행계획서와 다르게 정한 점 (엔진 담당과 맞춰야 함):

- `deviation.alert`의 이탈 유형 필드 이름을 `type` 대신 `deviation_type`으로 했습니다. `type`은 메시지 이름에 쓰기 때문입니다. 값은 `skip`(누락), `repeat`(반복), `adlib`(애드리브)입니다.
- 이탈하면 `return_cue_id: null`로 한 번, 대본으로 돌아오면 같은 `since`에 `return_cue_id`를 채워 한 번 더 보냅니다.
- 시각(`since`, `sent_at`)은 epoch 밀리초입니다.
- `input.status`는 음량 막대를 그려야 해서 모의 서버는 인식 주기마다 보냅니다. `audio_level`이 0이면 입력 없음으로 봅니다.
- 화면은 5초간 메시지가 없으면 "엔진 응답 없음"을 띄웁니다. 그래서 엔진도 `input.status`를 상태가 바뀔 때만이 아니라 주기적으로(1~2초) 보내 줘야 합니다.
- `position.update`에 `transcript`(인식 글자)를 추가했습니다. 수행계획서 화면 설계 ⑤ 인식 글자에는 있지만 메시지 표에는 없던 필드입니다.
- `session.start`에 `input`(`file` / `mic` / `text`)을 추가했습니다. 화면에서 소리 입력을 고르기 위해서입니다. **실서버는 아직 이 값을 읽지 않습니다** (엔진 담당에 요청).
- 화면 → 엔진 메시지 `test.say {text}`를 추가했습니다. 대사 입력 모드에서 입력한 글자를 음성인식 결과 한 번으로 보고 추적하는 테스트용입니다. **실서버는 아직 받지 않습니다** (엔진 담당에 요청).
- 화면 → 엔진 메시지 `subtitle.send {text, source}`를 추가했습니다 (`source`: `recognized` 인식 수정 / `manual` 직접 작성). 애드리브 임시 자막 송출용입니다. **수행계획서에서는 보조 화면에 송출 기능이 없고(R3) 애드리브 임시 자막은 이번 학기 범위 밖(Won't)이었으므로 팀 합의가 필요합니다.** 실서버와 송출 프로그램은 아직 받지 않습니다 (엔진 담당 · 2단계 송출 프로그램 연동에 요청). 모의 서버는 받은 내용을 로그로만 남깁니다.
- 보조 화면에 대본 목록을 띄우려면 화면도 큐 목록이 필요합니다. 지금은 화면이 큐 CSV를 직접 읽습니다. 엔진이 큐 목록을 보내 줄지 정해야 합니다.

## 큐 CSV (임시)

```
id,order,type,speaker,text
845,845,dialogue,지영,처음부터 다시 얘기해 줄래요?
```

`type`은 `dialogue/lyric/sound/blackout/notice`나 `대사/가사/음향/암전/안내` 둘 다 받습니다. 열 구성은 데이터 담당과 확정되면 `src/cues.ts`의 `CUE_CSV_COLUMNS`를 고칩니다.
